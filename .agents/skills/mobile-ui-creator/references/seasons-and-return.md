# Seasons and returning players

## Event calendar

Keep a stable entry in the Events section. In the list, show the named event, its phase and the next relevant deadline. Put the full participation window, access requirement, player progress and the earned-reward deadline in the card. Use absolute dates, times and a visible time zone. If you add a countdown, pair it with the absolute deadline.

Use the service's schedule and server time to determine the phase. At the start timestamp an eligible player can participate. At the end timestamp participation closes and any separate claim window begins. At the claim cutoff the window closes. Use confirmed reward state to decide whether a player can claim inside that window. Keep progress and a written outcome visible after closure. If the schedule or reward state is unavailable, explain that the game is checking it and refresh before offering the affected action.

| Phase | What the player sees and can do |
| --- | --- |
| Upcoming | Start time, access requirement and what will count toward progress. |
| Running | End time and current progress, with a participation action for eligible players or the requirement they still need to meet. |
| Claim window | Participation has ended. Show the separate claim cutoff, final progress and the confirmed reward state. Offer collection for an earned, unclaimed reward. |
| Closed | Show final progress and the reward outcome, such as collected, unearned or expired. Keep the card available for review. |

Keep the filter, list position and originating control when a card opens. Restore them on Back. When a refreshed card disappears from the filtered list, preserve the filter and return focus to the nearest remaining row, or to the filter if the list is empty.

## Returning after a season change

Show the most relevant changes since the last visit, the player's saved objective and one primary action that opens that objective. Use the latest confirmed checkpoint. Provide a way to dismiss the summary and reach the normal Progress screen. Keep previous events as secondary links and resolve their current phase before showing an action. An event from the previous season can still have an open claim window.

Test a first visit to the new season with a saved checkpoint and a previously tracked event. Follow the progression action and confirm the exact objective resumes. Open the old event from the summary with an open claim window and with an expired reward. Verify that the event reflects the current state and that the player can still reach their saved objective.

## Verification

- Check the timestamps immediately before and at the start, participation end and claim cutoff. Exercise an ineligible player, an earned reward and a previously collected reward. Recheck what happens when the card is open as a phase changes or the app resumes.
- On a compact viewport, open a scrolled row from a non-default filter and return using Back. Check scroll, focus, a long title and reduced motion. Record which results came from fixtures and which were confirmed by the game service.

[Supercell Events & Event Pass](https://support.supercell.com/clash-of-clans/en/articles/events-2.html) shows current and upcoming events together and describes a separate post-event period. [Warframe Returning Player Guide](https://www.warframe.com/en/news/returning-player-guide) pairs a summary of changes with a path back to the main story.
